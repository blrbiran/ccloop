**每条 finding 必须带：**
- **锚点**：符号名 + 文件（行号只作辅助，已实测漂移）

- **分级依据**（不是「保险起见」）
- **修法建议**（若不显然）

**分级校准**：Critical = 数据丢失 / 承重前提被证伪 / 读者按字面办事会删掉不该删的东西。
Important = 论证有洞、缺关键约束、义务只在文字上兑现。Minor = 引文瑕疵、可延后。
**不要把 nitpick 标成 Critical。也不要因为想显得温和就把真洞降级。**

**结论必须给明确判词**：`可开门 / 需修复环 2 / 不可开门`，并给 1–2 句技术理由。

**§8「我没做完的事」是强制节，不许空。** 本仓库的规矩：自报未验项比虚假完整更值钱。
